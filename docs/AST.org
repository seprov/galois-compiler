* Notes

  Should an Operator be explicit or implicit?

  If an Operator contains is serial, then we have to assign it to processor and we are done.

  If an operator contains a parallel loop, we may need to "flatten" it -- how to do this with minimum time and space?

* The Fully Expanded Pipeline Representation

  WL

  |
  v

  Op

  |
  v

  WL

  etc.

  Where Op can be a regular operator (straight down) or it can be a
  irregular operator (talks to left and right to figure out where to
  place its outputs). 

  There could be Operators (like Neighbourhood discovery in DMR) that
  don't know how much work they're going to do.

  There should also be arbitration logic to ensure concurrency and
  consistency?

  End result is a pipeline that can be replicated horizontally for
  increased parallelism.

  Right-and-left edges on Operators could be via shared memory inside
  a thread block

* Requirements

  Should be able to switch from async to sync worklist processing
  Should be able to generate topo version from data-driven version
  Should be reasonably generic and allow implementations of different variant of algorithms
  
  Break up large/Merge small operators depending on information flow?
